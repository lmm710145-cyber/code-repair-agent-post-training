# 实现状态与验证边界

本仓库从本机研究代码提取协议、上下文管理、pytest 观测、奖励规则和内存友好的概率计算，重新组织成配置驱动的 Python 包。历史实验的绝对路径、API 凭据、数据资产、累计运行记录和自动选取 checkpoint 均未打包。

## 已提供可执行入口

- 已审查 PR 的生产／测试补丁拆分与代码快照构造；仓库隔离与数据 schema 检查。
- 共享依赖 Docker 环境、真实 mini-SWE-agent 工具交互、F2P/P2P 与扩大回归认证。
- Kimi compatible API 采集、请求上限、自动分诊、逐动作具名审查接口。
- 原始可见上下文的 SFT 数据导出、任务级 holdout、分层样本抽样、LoRA 训练入口。
- 基座或 SFT adapter 初始化、课程任务选择、G=16 采样、同奖励组排除、经典 GRPO 更新与 checkpoint。
- 起点对照的 dev/test pass@1/pass@5 与行为统计。

## 需使用者或后续工作完成

- 来源判断、题意重构、描述与测试一致性判断、逐动作语义结论和独立人工复核。规则不能替代这些审查。
- 300 题数据包、第三方代码许可核对、真实依赖镜像、模型与权重下载、teacher endpoint 和密钥。
- 仓库特有的环境修复。新通用环境不能保证替代全部历史仓库的定制 bootstrap，导入后必须重新认证。
- 步骤级因果信用分配、语义重复检测、反事实 PRM 或价值模型。
- 训练 runner 自动 holdout NLL、官方 SWE-bench Lite 全链路适配。
- 具体实验指标与 checkpoint 选择。

## 本次验证

CPU 测试覆盖严格 Action 解析、上下文裁剪、奖励边界、重复状态与反馈判断、同奖励组、课程恢复、分层采样及 pass@k 统计。另以一个合成修复任务通过真实 Docker 与 mini-SWE-agent 验证了构造、两次认证、工具交互、最终隐藏测试与动作审查包生成。

本次没有调用付费教师，也没有占用正在运行实验的 GPU 重跑 SFT/GRPO。因此“本地 smoke 可运行”不等于新整理后的所有 GPU 路径已通过端到端生产验收；正式批量训练前应先用小数据完成容量与梯度检查。

## 与旧实验的关系

- 当前运行中的旧实验和其冻结配置未被迁移或修改，新仓库是独立目录。
- 新仓库的课程策略、分层 SFT 和可选 SFT 初始化属于新的可配置实现，不应倒推为旧实验已经采用它们。
- 新 GRPO 将同奖励组从有效 loss 分母排除；旧实验可能将它们保留在分母。两者不是逐位复现实验。
- 历史模型成功率和教师样本规模不在 README 固定填写；由指定外部数据版本与新运行记录生成。
