# GRPO：评分、采样与更新

## 结果信用与行为费用

评分先处理环境无效与修改合规，再确定结果基础分，最后扣行为费用和独立终止费用。修复验收依据最终补丁的 F2P/P2P 与扩大回归测试，不依据代理的“完成”声明。

令 B 为结果基础分，C 为各行为事件费用之和，E 表示轮数或累计输出 token 已耗尽且环境未接受最终提交：

```text
R = B - min(C, 0.5) - 0.25 * E
```

环境无效不提供奖励；修改违规或观测器篡改直接记 -1。B 在成功时为 1、普通失败为 0、回归为 -0.25。已修好的补丁不会仅因 `RepeatedFormatError` 终止而失去成功基础分。墙钟超时、单条 bash 超时或工具输出折叠不自动计入轨迹预算耗尽。

格式错误每次 .02；重复每次 .02；可以明确归因于输出长度导致的未闭合 Action 每次 .01，同一输出不重复收取格式与截断费用。模型输出完整但恰好达到长度限制时不因长度本身扣分。

重复必须是连续相同的检查／测试命令，相关文件状态与原始反馈 hash 相同，第三次起计费。修改后重新检查、收到新反馈、复杂 shell 脚本与不确定的语义重复不自动计费。本规则追求可审计性，召回率有限。

## G、课程与同奖励组

每个任务 G=16；这与 vLLM 并发数 4 不同。16 条轨迹来自同一 adapter 和策略版本，各有不同 seed，不因其中某条成功而提前结束采样。

课程按仓库平衡，依据带先验和时间衰减的训练成功率 p 估计组内可能出现信号的程度：

```text
score = floor + 1 - p^G - (1-p)^G
```

探索概率保证任务仍有机会被采样。统计只来自训练任务的完整组，不使用 dev/test 成功率。基于成功率的课程不会捕捉全部行为奖励方差，这是该近似的限制。

每个任务组的优势为 `(reward - mean) / (population_std + 1e-6)`。同奖励组记录后排除；整个批次无信号则不执行 optimizer.step、不递增更新计数，继续采样。最大采样轮数与连续无信号轮数是防止无限运行的保护，触发时不能宣称训练完成。

## 概率与信用分配边界

vLLM 仅负责采样。采样完成后释放服务进程，Transformers 加载同一 adapter 与优化器状态。更新前重算 p_old，梯度前向得到 p_new；使用经典 clipped surrogate，单个批次只更新一次，默认没有 KL 项。

vLLM 的 q 与 Transformers 的 p_old 差异会记入审计，但不进入损失权重。这沿用“不进行采样／训练概率补偿”的实验选择：检查 adapter 版本和重放一致性可以发现陈旧策略，却不能证明后端分布完全一致。

本实现按轨迹内部输出 token 平均，再在有效轨迹间平均。虽然违规事件定位到步骤，最终优势仍是整条轨迹的标量。成功轨迹中的错误动作仍可能获得正优势。更精确的动作归因、PRM、价值函数或分支 rollout 属于后续扩展，没有在这里默认加入。

组内标准化还会改变奖励绝对尺度的含义，例如 `[1,0,0,0]` 与 `[0.5,0,0,0]` 的优势几乎相同。费用设计提供轨迹排序信号，不应把扣分幅度直接理解为等比例梯度强度。惩罚“不该做什么”也不天然比奖励“该做什么”更能防止 reward hacking。
